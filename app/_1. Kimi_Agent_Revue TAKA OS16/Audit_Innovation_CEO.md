# II. LES 8 INNOVATIONS DE RUPTURE OUBLIÉES

## 1. AO Simulator (Monte-Carlo Stratégique)

**Concept** : Avant de déposer, TAKA lance une **simulation de 100 scénarios** avec données attributions publiques.

**Workflow** :
```
Entrée : AO détecté + historique attributions du même MO
       + marge cible + 3 stratégies de prix

Simulation :
- Scénario A : Marge 25%, prix moyen du marché
- Scénario B : Marge 18%, prix agressif (percentile 10)
- Scénario C : Marge 30%, prix premium avec valeur technique ajoutée

Résultat :
- Probabilité Scénario A : 34%
- Probabilité Scénario B : 67% (risque marge faible)
- Probabilité Scénario C : 12%

Recommandation : "Pour ce MO qui attribue à 70% au prix,
je recommande Scénario B avec marge à 20%."
```

**Rupture** : L'artisan dépose "à l'aveugle" → TAKA transforme en **décision stratégique quantifiée**.

## 2. Pré-AO / Ghost AO (Avantage Temporel)

**Concept** : TAKA scrute les **avis d'information préalable**, budgets votés en conseil municipal, consultations préalables.

**Workflow** :
```
Détection : "Le conseil de Villeurbanne a voté 180K€ pour
            la réhabilitation éclairage du gymnase Jean-Moulin.
            L'avis préalable sort dans 3-4 semaines."

Action :
- Alerte : "Ghost AO détecté. Préparez votre mémoire type."
- TAKA pré-rédige le mémoire avec spécifications standards.
- Quand l'AO sort officiellement : dépôt en 24h au lieu de 5 jours.
```

**Rupture** : Tu déposes avant que tes concurrents aient vu l'AO. **Intelligence anticipatoire**.

---

## 3. Digital Twin Soumissionnaire

**Concept** : Après 3 mois, TAKA connaît l'entreprise mieux que son dirigeant. Jumeau digital de la capacité soumissionnaire.

**Applications** :
- **Réponses auto aux questions techniques** : génère réponse basée sur vrais protocoles (extraits mémoires précédents + données chantier)
- **Personnalisation du ton** : style technique/sec vs commercial/enthousiaste
- **Détection mensonges involontaires** : "Vous déclarez 12 salariés mais vos fiches de paie en montrent 8 → Corriger ?"

**Rupture** : Le mémoire n'est plus un template. C'est la **voix numérique authentique** de l'entreprise.

## 4. Marketplace Groupement (Écosystème TAKA)

**Concept** : AO alloti. L'entreprise ne fait que l'électricité, mais l'AO demande aussi plomberie + chauffage.

**Workflow** :
```
TAKA : "Vous ne pouvez pas répondre seul. J'ai identifié
3 partenaires certifiés dans votre zone qui utilisent TAKA :

1. SARL Dupont Chauffage (Lyon, 8 salariés, Qualibat)
   → A déjà travaillé avec vous sur CH Saint-Étienne
2. EURL Martin Plomberie (Villeurbanne, 5 salariés)

Je peux rédiger la lettre d'intention de groupement,
pré-remplir les pièces des 3 entreprises, et déposer
un dossier coordonné. Commission TAKA : 0,3% du montant."
```

**Rupture** : TAKA ne sert pas une seule entreprise. Il crée un **réseau d'entreprises augmentées**.

## 5. Mode Panique / Turbo (Délai < 5 jours)

**Concept** : AO avec 3 jours de délai. La plupart ignorent car impossible.

**Workflow** :
```
Activation Mode Panique :
- Désactivation Parlement (délibération 1 tour direct)
- Forçage template mémoire le plus proche historique
- Holo-1 en "Fast Mode" : pas validation étape par étape,
  capture vidéo complète pour audit post-dépôt
- Détection auto pièces disponibles (KBIS < 3 mois,
  attestation URSSAF déjà en stock)
- Rédaction accélérée : mémoire réduit aux sections obligatoires

Résultat : Dépôt possible en 36h au lieu de "impossible".
```

**Rupture** : TAKA transforme les AO "impossibles" en opportunités capturables. **Aucun concurrent ne fait ça**.

## 6. Apprentissage Actif des Procédures (Holo-1 Observer)

**Concept** : Holo-1 ne sert pas qu'à déposer. Il **apprend**.

**Workflow** :
```
Mode Professeur activé sur logiciel interne "Ciel Devis"

Holo-1 observe l'écran pendant que l'utilisateur :
1. Se connecte
2. Crée un nouveau devis
3. Ajoute 3 lignes d'articles
4. Applique une remise
5. Génère le PDF

TAKA mémorise :
- Séquence exacte de clics (coordonnées + noms de champs)
- Temps de chargement entre pages
- Erreurs rencontrées (popup, alertes)

La semaine suivante :
"Refais le devis standard EDF pour client Martin"
→ TAKA reproduit la séquence exacte. L'utilisateur valide.
```

**Rupture** : TAKA devient le **macro-intelligent** de toute l'entreprise. Porte d'entrée vers la V3 "Général".

## 8. Benchmarking Concurrentiel Automatique (Attributions Publiques)

**Concept** : TAKA agrège et analyse les **attributions publiques** (obligatoires en marchés publics).

**Workflow** :
```
Pour chaque MO suivi :
- Récupère attributions des 24 derniers mois
- Analyse : qui a gagné, à quel prix, quel délai, quelle note

Insight :
"Le CH de Lyon attribue lots électricité à 90% au prix le plus bas.
Le gagnant habituel est SARL ElecSud (Lyon 7ème), 12% en dessous
 de votre niveau. Recommandation : ne déposez que si vous pouvez
 aligner -10%, ou si vous avez un atout technique majeur
 (ex: certification HQE que ElecSud n'a pas)."

TAKA met à jour automatiquement le poids "intelligence" du scoring.
```

**Rupture** : TAKA connaît le marché mieux que les Chambres de Métiers. **Renseignement économique** automatisé.

# III. ÉVOLUTIVITÉ DES DIMENSIONS DE SCORING

## Architecture Plug-in Dimension (YAML)

```yaml
# verticals/ao/dimensions/custom_dimension.yaml
dimension_id: "rse_environment"
name: "Compatibilité RSE"
version: 1
description: "Évalue si l'AO valorise les critères RSE et si l'entreprise y répond"

input_schema:
  - ao.criteres_environnementaux  # bool
  - ao.materiaux_biosources_req   # bool
  - enterprise.certifications_rse   # list
  - enterprise.demarche_dechets     # bool

rules:
  - condition: "ao.criteres_environnementaux == false"
    action: "score = 50"
  - condition: "ao.materiaux_biosources_req == true AND 'ISO14001' in enterprise.certifications_rse"
    action: "score = 100"
  - condition: "ao.materiaux_biosources_req == true AND enterprise.demarche_dechets == false"
    action: "score = 10"
    strict: true  # Éliminatoire

default_weight: 0.10
```

**Fonctionnement** :
1. Admin upload le YAML
2. Scoring Engine l'enregistre dans RuleRegistry
3. Nouveaux AO évalués avec cette dimension
4. UI affiche automatiquement nouveau rayon sur graphique radar
